# 隐私政策

> 生效日期：2026-07-21 ｜ 版本：v1.0 ｜ 隐私官邮箱：privacy@deadman.local（占位）

本政策适用于 deadman 身后事多智能体引导平台（以下简称「本平台」）所提供的全部信息引导、终活笔记、数字遗产保险库、遗码通（Decedent ID）、悼文生成器、通知信函生成器、dead man switch 等服务。

本政策依据《中华人民共和国个人信息保护法》（PIPL）、《数据安全法》、《网络安全法》制定。涉及境外用户时，同步遵循 GDPR 等当地法规。

## 一、信息收集范围

本平台严格遵循「最小必要」原则（PIPL 第 6 条），仅收集完成当前任务所必需的信息。我们将可收集的个人信息按 PIPL 第 28 条敏感度分为三类：

### 1.1 一般个人信息（PII 类别清单）

| 类别 | 字段示例 | 收集场景 | 是否必需 |
|------|---------|---------|---------|
| 账户标识 | email、显示名 | 注册 / 登录 | 必需 |
| 认证凭据 | 密码哈希（PBKDF2-HMAC-SHA256）、salt | 注册 / 登录 | 必需 |
| 用户画像 | 与逝者关系、地点、去世日期、当前办理阶段 | onboarding wizard | 可选 |
| 终活笔记 | 个人信息、家庭关系、医疗意愿、遗嘱意图、财产清单 | 用户主动填写 | 可选 |
| 通知信函参数 | 逝者姓名、申请人姓名、申请关系、收件机构 | 用户主动填写 | 可选 |
| 悼文参数 | 逝者姓名、关系、性格特点、记忆片段、价值观 | 用户主动填写 | 可选 |
| 操作日志 | 访问时间、IP、User-Agent、调用的 API 路径 | 全程被动收集 | 必需（运维） |

### 1.2 敏感个人信息（PIPL 第 28 条）

下列信息属于敏感个人信息，**单独告知 + 单独同意**后才会处理：

- 身份证号（仅在生成通知信函时用户主动填入脱敏字段，本平台不存储完整号码）
- 银行卡号 / 金融账户（本平台**不收集**完整号码；终活笔记中若用户填写，建议填掩码）
- 健康信息 / 病历（仅在涉及医疗导航场景时由用户主动提供）
- 14 周岁以下未成年人信息（本平台**不主动收集**）

### 1.3 本平台明确不收集的信息

- ❌ 完整身份证号、银行卡号、密码、短信验证码
- ❌ 生物识别信息（指纹、人脸、声纹）
- ❌ 宗教信仰、政治观点（除非用户在终活笔记中主动填写遗嘱意图）
- ❌ 行踪轨迹、精准位置（仅收集到省/市级）

智能体**不得要求**用户提供上述「不收集」清单中的任何信息。如用户主动发送，将提示「请不要在对话中发送完整证件号/密码/验证码」并立即清除处理缓存（不入库）。

## 二、使用目的

依据 PIPL 第 13 条第（二）项「为订立、履行合同所必需」，以及第（三）项「为履行法定职责或者法定义务所必需」，我们使用您的信息用于以下目的：

1. **核心服务交付**：根据用户输入引导身后事办理流程、生成终活笔记、生成通知信函与悼文
2. **账户与认证**：识别用户身份、签发 JWT 会话令牌、维护登录态
3. **跨阶段连续性**：在 case_id 维度下记录已办理进度，避免重复询问
4. **遗码通与遗物保险库投递**：当 dead man switch 触发时，将用户预设的数字遗产投递给指定受益人
5. **服务改进（去标识化）**：将对话日志用于服务质量和故障排查，做匿名化后再用于产品改进
6. **安全与合规**：检测滥用、欺诈、违规行为（如批量爬虫），保留操作日志用于合规审计
7. **法定义务履行**：依法配合执法机关的调查请求

## 三、处理依据

本平台对个人信息的处理依据以下任一合法依据（PIPL 第 13 条）：

- **合同履行**：完成用户请求的服务所必需（如生成通知信函、生成悼文）
- **法定义务**：依据《数据安全法》《网络安全法》保留访问日志、配合监管要求
- **同意**：在 onboarding wizard 中单独告知并取得用户同意；用户随时可撤回同意
- **紧急避险**：在用户出现自伤/自杀风险时（safety-protocol L0），为保护用户人身安全可临时扩展信息使用范围

## 四、加密与存储

### 4.1 密码加密

- 用户密码使用 **PBKDF2-HMAC-SHA256** 算法加密存储，迭代次数 **100,000 次**（NIST SP 800-132 推荐，OWASP 2023 同步推荐）
- 每个用户使用独立的 **128 位随机 salt**（16 字节）
- 服务端不存储明文密码，不存储可逆加密的密码

### 4.2 邮箱索引

- 邮箱使用 HMAC-SHA256 + 服务端密钥做单向索引存储，防止拖库后撞库
- 服务端密钥单独存放于 `~/.deadman/auth/jwt_secret`，文件权限 `0600`

### 4.3 数字遗产保险库（per-user passphrase）

- Vault 内容使用 per-user passphrase 派生的密钥加密
- 密钥派生同样走 PBKDF2-HMAC-SHA256，迭代次数 100,000 次
- 服务端**不存储 passphrase 明文**，passphrase 由用户离线保管；丢失后内容不可恢复

### 4.4 会话令牌

- JWT 令牌签名算法 HS256，密钥与服务端 secret 共用
- 默认有效期 7 天，到期前 1 天可调用 `/api/auth/refresh` 续期

### 4.5 存储位置

- 用户数据存储于服务器本地文件系统（`~/.deadman/`），文件权限默认 `0600`
- 不使用第三方云存储；不使用第三方数据库托管
- 不做主从复制；备份由部署方自行决定

### 4.6 传输加密

- 生产部署应启用 HTTPS / TLS 1.2+
- 开发环境可降级 HTTP，但**不得承载真实用户数据**

## 五、共享与披露

### 5.1 默认不向第三方共享

本平台**默认不向任何第三方共享**您的个人信息，包括但不限于：

- ❌ 不与殡仪馆、殡葬服务机构分成或共享
- ❌ 不向律师、公证处、保险公司转介分成
- ❌ 不向广告平台、数据分析平台共享
- ❌ 不向模型训练服务提供商共享对话内容用于训练

### 5.2 法定披露情形

依据 PIPL 第 23 条，下列情况可向第三方披露：

1. 与刑事侦查、国家安全机关、检察机关、法院调查取证相关（依据《刑事诉讼法》《国家安全法》）
2. 与行政机关依法履行的行政调查、行政处罚相关（依据《行政处罚法》《数据安全法》）
3. 用户书面同意的特定场景（如主动发起通知信函投递给指定机构）
4. dead man switch 触发后，按用户预设将投递内容交付给指定受益人（视为用户预先同意）

### 5.3 委托处理

本平台当前**不委托第三方处理**用户个人信息。如未来引入云服务商（如日志分析），将：

- 单独告知用户委托方名称、处理目的、方式、信息种类
- 与受托方签订数据处理协议（DPA），约束其不得用于其他目的
- 用户有权拒绝

## 六、跨境传输

### 6.1 默认不跨境

本平台默认在中国大陆境内处理和存储用户数据，**不主动向境外传输**。

### 6.2 跨境情形

涉及下列场景时可能涉及跨境数据传输，本平台将依据 PIPL 第 38/39/40 条取得用户**单独同意**后才会执行：

- 跨境继承场景：用户主动指定境外受益人接收数字遗产
- 跨境医疗：用户主动选择境外医疗机构咨询
- 跨境法律事务：用户主动联系境外律师

跨境传输前将单独告知：
- 境外接收方的名称、联系方式
- 处理目的、方式、信息种类
- 用户在境外接收方所在国家/地区行使权利的方式和程序

## 七、用户权利

依据 PIPL 第四章，您对个人信息享有以下权利：

### 7.1 知情权与决定权

您有权知道本平台如何处理您的个人信息，并有权限制或拒绝（PIPL 第 44 条）。

### 7.2 查询与复制权

您可通过以下端点查询和复制您的个人信息：
- `GET /api/auth/me`：查询账户基本信息
- `GET /api/ending-note`：查询您的终活笔记
- `GET /api/vault/items`：查询您的数字遗产保险库条目
- `GET /api/cases`：查询您的案例列表
- `GET /api/support/tickets`：查询您的客服工单
- `GET /api/onboarding`：查询您的 onboarding 画像

### 7.3 更正与补充权

您可通过相应端点更正、补充个人信息（PIPL 第 46 条）。

### 7.4 删除权

下列情形下，您可请求删除个人信息（PIPL 第 47 条）：
1. 处理目的已实现、无法实现或者为实现处理目的不再必要
2. 本平台停止提供服务，或者保存期限已届满
3. 您撤回同意
4. 本平台违反法律、行政法规或者违反约定处理个人信息
5. 法律、行政法规规定的其他情形

### 7.5 撤回同意

您可随时撤回之前给予的同意（PIPL 第 15 条）。撤回不影响撤回前基于同意的处理活动的效力。撤回方式：
- 在 Web UI 退出登录并删除本地 token
- 提交客服工单请求删除全部数据
- 直接调用 `DELETE /api/vault/items/<id>` 删除单条数据

### 7.6 投诉权

您有权对本平台的个人信息处理活动提出投诉（PIPL 第 50 条）：
- 通过 `POST /api/support/tickets` 提交投诉工单（category=「投诉」）
- 通过隐私官邮箱：privacy@deadman.local（占位）

我们将自收到投诉之日起 **15 个工作日内**回复。

## 八、未成年人特别保护

### 8.1 年龄限制

- 本平台面向 14 周岁以上用户提供服务
- 14 周岁以下未成年人**不得注册**本平台账户
- 14-18 周岁的未成年人注册账户需监护人同意

### 8.2 未成年人信息处理

- 收集未成年人个人信息前必须取得监护人同意（PIPL 第 31 条）
- 涉及未成年人敏感信息时采取更严格保护措施
- 监护人有权拒绝并要求删除

### 8.3 涉及未成年人继承的特殊提示

当继承/继承纠纷涉及未成年人权益时（如父母双亡的未成年子女继承），智能体将提示：
- 可能需要民政或法院介入
- 建议联系未成年人保护机构或当地民政局
- 不直接提供涉及未成年人的具体处置建议

## 九、数据保留期限

### 9.1 账户数据

- 账户注册信息（邮箱、密码哈希）：账户存续期间保留
- 账户删除后：**30 天**宽限期内可恢复；30 天后彻底清除

### 9.2 对话日志

- 对话日志默认**不长期存储**；如开启存储，保留 90 天后自动清除
- 事故记录保留 **2 年**用于改进，之后匿名化或删除

### 9.3 客服工单

- 已关闭工单保留 **2 年**用于质量回溯
- 投诉类工单保留至投诉事项完全解决后 **3 年**

### 9.4 数字遗产保险库

- 用户主动删除：立即清除
- 已投递给受益人：投递日志保留 90 天，内容本身由受益人保管

### 9.5 dead man switch 触发记录

- 触发确认（cooldown 期间）：可随时取消
- 执行完成后：记录保留 90 天，用于审计

### 9.6 法定保留

- 依据《网络安全法》第 21 条，网络日志保留不少于 **6 个月**
- 依据《电子商务法》第 31 条，交易相关数据保留 **3 年**

## 十、Cookie 与本地存储

### 10.1 Cookie

本平台 Web 端**不使用 Cookie**追踪用户。会话状态通过 JWT 令牌承载。

### 10.2 LocalStorage

Web 端使用 LocalStorage 存储：
- `deadman_token`：JWT 令牌（关闭浏览器后保留）
- `deadman_disclaimer_dismissed`：免责声明是否已关闭（标记位）
- onboarding 完成状态（仅作 UI 提示）

退出登录时清空 `deadman_token`；其他存储项可手动清除。

### 10.3 客户端不存储敏感信息

- 客户端**不存储**密码明文、身份证号、银行卡号等敏感信息
- 数字遗产保险库的 passphrase 由用户离线保管，**不入 LocalStorage**

## 十一、安全事件响应

### 11.1 应急预案

依据 PIPL 第 57 条，本平台制定并组织实施个人信息安全事件应急预案：

1. **发现与确认**：24 小时内确认是否构成安全事件
2. **影响评估**：评估泄露范围、受影响用户数、风险等级
3. **补救措施**：立即切断泄露源、加固受影响系统
4. **用户通知**：通过工单系统、邮件、首页公告通知受影响用户
5. **监管报告**：依据《数据安全法》向网信办、公安机关报告

### 11.2 通知内容

发生安全事件时，将在 72 小时内通知用户：
- 事件类型
- 涉及的个人信息种类、范围
- 可能造成的危害
- 已采取的补救措施
- 用户可采取的自我保护建议
- 联系方式

### 11.3 内部安全措施

- 文件权限 0600 / 0644 严格控制
- 服务端密钥单独存放
- 部署后默认禁用 dev 模式（DEADMAN_ALLOW_QUERY_USER_ID=0）
- 操作日志保留 6 个月以上用于审计

## 十二、个人信息处理者义务

依据 PIPL 第五章，本平台作为个人信息处理者履行以下义务（PIPL 第 51 条）：

1. **内部管理制度**：制定并执行个人信息处理规程
2. **分类管理**：按敏感度对 PII 分类（见第一节）
3. **安全技术措施**：加密、去标识化、访问控制、审计日志
4. **权限合理确定**：内部人员按最小权限原则访问数据
5. **安全教育与培训**：定期对运维、开发人员进行合规培训
6. **应急预案**：制定并组织实施安全事件应急预案（见第十一节）
7. **个人信息保护影响评估（DPIA）**：涉及高风险处理活动时进行评估并保留记录
