## 一、常见问题（FAQ）

### Q1：本平台是真人客服还是 AI？

本平台是 **AI 信息引导工具**，所有响应由智能体生成，不是真人。本平台不替代律师、医生、政府工作人员，不代办任何手续。涉及关键决策请咨询持牌专业人士。

### Q2：我刚刚失去亲人，应该先做什么？

依据本平台 skills/death-aftercare-guide 流程，第一时间：
1. **开具死亡证明**：在医院或户籍地派出所
2. **联系殡仪馆**：遗体接运、冷藏、火化登记
3. **办理户口注销**：户籍地派出所
4. **数字账户处理**：微信、支付宝、银行账户的注销或继承
5. **遗产继承**：可咨询公证处或律师
6. **社保抚恤金申领**：12333 社保咨询热线

可调用 `GET /api/ending-note/guide/next` 获取下一章引导。

### Q3：本平台能否替我去办理手续？

**不能**。本平台是信息引导工具，**不代办任何手续**。死亡证明请到医院/派出所开具，火化请直接联系殡仪馆，户口注销请到户籍地派出所。

### Q4：终活笔记是不是法律文件？

**不是**。终活笔记（エンディングノート）是个人意愿的整理记录，**不是法律文件**，不替代遗嘱、信托、医疗预嘱。如需法律效力，请咨询律师/公证处办理正式文件。

### Q5：case_id 是什么？是官方编号吗？

case_id 是本平台为单个逝者事务生成的**内部追踪 ID**，仅用于跨阶段状态管理。**不冒充任何官方编号**（不冒充公安系统的死亡证编号、不冒充户籍注销编号、不冒充银行账户编号）。

### Q6：我的密码是如何存储的？

密码采用 **PBKDF2-HMAC-SHA256** 算法加密，迭代 100,000 次，每用户独立 128 位随机 salt。本平台**不存储明文密码**，且无法反向获取明文。详见《隐私政策》第四节。

### Q7：数字遗产保险库的 passphrase 丢失了怎么办？

**无法找回**。passphrase 由您自行保管，本平台不存储明文。丢失后保险库内容**不可恢复**。请将 passphrase 离线保管（如纸质备份存放于保险箱）。

### Q8：dead man switch 如何工作？会误触发吗？

dead man switch 需要您定期 check-in（默认 30 天一次）。连续 missed 阈值（默认 3 次）后进入「待确认」状态，需要紧急联系人和继承人确认。确认后进入 **7 天冷静期**，期间您可随时取消。冷静期过后才会执行预设动作。详见 `deadman_switch` 模块。

### Q9：如何提交反馈或投诉？

通过 Web UI「帮助」入口提交客服工单，或调用 `POST /api/support/tickets`：
- `category`：咨询 / 反馈 / 投诉 / 数据删除 / 跨境合规
- `priority`：低 / 普通 / 紧急
- 工单创建后将获得 `ticket_id` 用于追踪

### Q10：对话内容会被存储吗？会用于训练吗？

依据《隐私政策》第二节，对话日志默认**不长期存储**。本平台**明确不使用**您的对话内容用于模型训练。

### Q11：跨境继承涉及哪些合规要求？

跨境继承涉及 PIPL 第 38/39/40 条：
- 跨境传输需取得您的**单独同意**
- 需告知境外接收方名称、联系方式、处理目的
- 需告知您在境外所在国家/地区行使权利的方式

调用客服工单（category=「跨境合规」）可获得进一步指引。

### Q12：未成年人可以使用本平台吗？

14 周岁以下未成年人**不得注册**。14-18 周岁需监护人同意。涉及未成年人继承的事项将提示联系民政或法院。

### Q13：智能体的响应不准确怎么办？

智能体提供的信息可能过时或不适用于具体个案。如发现：
- 通过客服工单反馈（category=「反馈」）
- 涉及具体电话/费用/时限请拨打 12345 核实
- 涉及法律问题请咨询律师

### Q14：如何删除我的账户和数据？

通过客服工单提交删除请求（category=「数据删除」）：
- 进入 30 天宽限期，期间可恢复
- 30 天后账户数据彻底清除
- 法定保留的日志（6 个月-3 年）按法律规定保留

## 三、自助工具

### 3.1 终活笔记（エンディングノート）

引导您整理个人信息、家庭关系、医疗意愿、遗嘱意图、财产清单等内容。

- 入口：登录后访问主界面 → 「终活笔记」
- API：`GET /api/ending-note`、`POST /api/ending-note/section`
- 引导：`GET /api/ending-note/guide/next`
- 完整度评分：`GET /api/ending-note/completion`
- 共享给家庭：`POST /api/ending-note/share`

**重要提示**：终活笔记不是法律文件，如需法律效力请咨询律师/公证处。

### 3.2 数字遗产保险库（Vault）

加密存储待投递的数字内容（密码、文件、密钥、笔记），按触发条件投递给指定受益人。

- 入口：登录后访问主界面 → 「保险库」
- API：`GET /api/vault/items`、`POST /api/vault/items`、`POST /api/vault/items/<id>/trigger`
- 受益人管理：`GET /api/vault/beneficiaries`
- 继承查询：`GET /api/vault/inherited`

**重要提示**：passphrase 由您离线保管，丢失后内容不可恢复。

### 3.3 遗码通（Decedent ID）

为逝者事务生成内部 case_id 与时间线，便于跨阶段状态管理。

- 入口：登录后访问主界面 → 「遗码通」
- API：`GET /api/cases`、`POST /api/cases`、`POST /api/cases/<id>/events`
- 时间线：`GET /api/cases/<id>/timeline`
- 归档：`POST /api/cases/<id>/archive`

**重要提示**：case_id 是内部 ID，不冒充任何官方编号。

### 3.4 悼文生成器

基于用户输入生成悼文、讣告、答谢词、墓志铭、追思会致辞。

- API：`GET /api/memorial/types`、`POST /api/memorial/generate`
- 支持 5 种文档类型、多种 tone / faith / language 选项

**重要提示**：AI 生成内容仅供参考，建议家属审阅修改后使用。

### 3.5 通知信函生成器

生成死亡通知、户口注销申请、保险申领等 8 种信函草稿。

- API：`GET /api/letters/types`、`GET /api/letters/template`、`POST /api/letters/generate`

**重要提示**：信函中的姓名、证件号、地址需用户自行核实后填入正式版本。

### 3.6 Dead Man Switch

失联触发机制，用于自动投递数字遗产、通知受益人。

- API：`POST /api/switch/init`、`POST /api/switch/checkin`、`GET /api/switch/status`
- 验证：`POST /api/switch/verify-contact`、`POST /api/switch/verify-heir`
- 取消：`POST /api/switch/cancel`

**重要提示**：触发后有 7 天冷静期，期间可取消。执行后不可逆。

### 3.7 规划完整度评分

评估当前用户在身后事规划上的完整度。

- API：`GET /api/plan-score`、`GET /api/plan-score/detail`

## 四、客服工单

### 4.1 提交工单

通过以下方式提交工单：

**方式 1：Web UI**

登录后点击侧边栏「帮助」→「提交工单」

**方式 2：API**

```http
POST /api/support/tickets
Authorization: Bearer <your_token>
Content-Type: application/json

{
  "category": "咨询",        // 咨询 / 反馈 / 投诉 / 数据删除 / 跨境合规
  "priority": "普通",        // 低 / 普通 / 紧急
  "subject": "工单标题",
  "description": "详细描述"
}
```

返回示例：
```json
{
  "ticket_id": "tkt-abc123def456",
  "status": "open"
}
```

### 4.2 查询工单

- 列出我的工单：`GET /api/support/tickets`
- 工单详情：`GET /api/support/tickets/<ticket_id>`

### 4.3 追加工单回复

```http
POST /api/support/tickets/<ticket_id>/replies
Authorization: Bearer <your_token>
Content-Type: application/json

{
  "content": "补充信息..."
}
```

### 4.4 工单状态流转

工单状态：`open` → `in_progress` → `resolved` → `closed`

- `open`：已创建，待客服处理
- `in_progress`：客服处理中
- `resolved`：已解决，等待用户确认
- `closed`：已关闭
